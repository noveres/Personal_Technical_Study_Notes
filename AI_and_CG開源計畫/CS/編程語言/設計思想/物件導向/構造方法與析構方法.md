### 構造函數
 
 >
 >在對象被創建時調用，常用來**初始化**對象內部的成員、進行必要的資源分配
 >

  具有以下幾個特性：

- **產生類 (Defining/Creating a Class)** 的 **實例** 中被自動調用
- 函數名與類名相同
- 沒有返回值
- 可以進行重載

>
>構造函數：本質是生成對象處理階段的處理邏輯，這個階段生成的就是這個類的對象，所以不需要返回某個結果
>

記憶體分配：
- 當執行 實例化 或 new 一個引用出來時，作業系統或執行期環境（Runtime）已經根據「類」這個模板的大小，**分配記憶體空間給這個實例了**
- 空間切好後，系統會立刻把這塊剛出生的記憶體交給 **構造函數** 進行內容的操作
  如：初始化就是進去這塊記憶體裡面，把裡面的屬性（數據）填上初始值。

>
>構造方法編譯器會自動幫我們隱式生成一個「無參數、內容為空」的構造方法
>

假設：

```c++
class Human {
public:
    std::string name;
    int age;
    // 這裡空空如也，什麼構造方法都沒寫
};
```

編譯器在編譯時，會默默地補上

```c++
Human() {
    // 內容是空的，什麼都沒做
}
```

依然可以順利調用`Human()`來生成對象，而程式不會報錯的原因。因為系統在「生成對象處理階段」，依然有這個自動生成的構造方法可以呼叫。

### 析構函數

 >
 >常在析構函數中對**動態申請的內存進行釋放**，或**執行外部資源的關閉**，如關閉文件、關閉資料庫連線等操作
 >

  具有以下幾個特性：

- 一個類別**只能有一個**析構函數
- **過程**必須明確不能有二義性，所以不能被重載（Overload）
- 系統會**自動**呼叫析構函數
- 析構函數**不能帶有任何參數與回傳值**，連 `void` 都不行
-  函數名與類名相同，但前面必須加上一個波浪號 `~`
  
Q：為什麼 **不需要** 而且 **不應該** 呼叫析構函數
A：
	主要原因可以拆解為以下三個核心問題
	- 「**二次釋放**」（Double Free）
	- 「**殭屍物件**」（Zombie Object）
	- 違反 **自動化**（RAII） 的程式設計觀念

>
>在沒有 GC 的 C++ 中，物件離開作用域會**立刻**執行析構函數，這叫「確定性析構」。
>
>但在有 GC 的現代語言中，物件沒人用了，它**不會立刻被釋放**。
>GC 什麼時候啟動？完全由執行緒和系統決定（通常是記憶體快滿的時候）。
>
>這就是為什麼像 Java 還要提供 `close()`，C# 要提供 `Dispose()`，Python 要提供 `__exit__` 這種「手動銷毀」的函數，就是為了**繞過 GC** **立刻** 外部資源（檔案、網路）還給作業系統
>

Q：既然我要自己寫 `delete`，那為什麼還說析構函數是『自動』的？
A：我們要明確「釋放資源」這件事，必須寫在「析構函數內部」；而「呼叫析構函數」這件事，才是編譯器自動做的。

以 C++ 為例
編譯器不會去猜什麼時候不用這塊記憶體
因此：
1. 必須在類別的**析構函數裡面**，親手寫下 `delete ptr;` 或 `free(ptr);`。告訴系統：「當這個物件要死掉的時候，請順便把我手上的這個指標給釋放掉。」
2. 編譯器負責監控物件的生命週期。一旦物件離開作用域編譯器就會**自動、絕對不會忘記地**去觸發那個析構函數。 例如：如區域變數碰到了函數結束的大括號 `}`

```c++
class Player {
private:
    int* Inventory; // 原生指標
public:
    Player() {
        Inventory = new int[100]; // 1. 主動申請資源
    }
    
    ~Player() {
        delete[] Inventory;       // 2. 主動寫好「怎麼釋放」
        std::cout << "背包記憶體已释放\n";
    }
};

void playRow() {
    Player p; // 物件 p 誕生
    // 執行邏輯...
}

 // 3. 函數結束！編譯器「自動」呼叫 p.~Player()
 // 4. 進而執行了裡面的 `delete[] Inventory`
```
