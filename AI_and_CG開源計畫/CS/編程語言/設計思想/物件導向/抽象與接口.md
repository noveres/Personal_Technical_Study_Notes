「提供訪問接口（Access Interface）」在軟體工程中，指的就是**一個類別（Class）或模組對外公開的、可以被安全呼叫的方法（Methods）與功能總和**。

 `public` 權限和 `Getter / Setter`，是最基礎、最典型的訪問接口。
詳見：[[屬性修飾符（Property Modifiers)]]


在設計大型專案或遵循物件導向設計原則時，提供訪問接口主要有以下幾種層次與模式：

## 1. 傳統類別接口（Class-Level Interface）

這是最常見的形式。我們將所有資料欄位設為 `private`，並**只暴露必要的 `public` 方法作為接口**，讓外部與物件進行互動。外部不需要知道裡面怎麼算的，只需要知道接口怎麼呼叫。

### 範例

```C++
class SmartLight {
private:
    int brightness = 0; // 私有屬性，不對外開放

public:
    // 訪問接口 1：開燈（隱藏了亮度設定的細節）
    void turnOn() {
        brightness = 100;
        std::cout << "燈已開啟，亮度調整至最大。\n";
    }

    // 訪問接口 2：關燈
    void turnOff() {
        brightness = 0;
        std::cout << "燈已關閉。\n";
    }

    // 訪問接口 3：微調亮度（提供安全檢查）
    void adjustBrightness(int level) {
        if (level >= 0 && level <= 100) {
            brightness = level;
        }
    }
};
```

## 2. 抽象接口類別（Pure Interface / Abstract Class）

當專案變大時，我們會希望「定義與實作分離」。這時候會定義一個**完全沒有實作細節的「純接口類別」**（在 Java/C# 中叫 `interface`，在 C++ 中叫包含「純虛擬函數 Pure Virtual Function」的抽象類別）。

這就像是制定一份**標準合約**，任何想扮演這個角色的類別，都必須實作接口所定義的功能。

### 範例

```C++
// 1. 定義一個「支付接口」合約
class IPaymentProcessor {
public:
    virtual ~IPaymentProcessor() {} // 虛擬析構函數
    virtual void pay(double amount) = 0; // 純虛擬函數：定義訪問接口
};

// 2. 實作合約 A：信用卡支付
class CreditCardPay : public IPaymentProcessor {
public:
    void pay(double amount) override {
        std::cout << "使用信用卡支付了 $" << amount << "\n";
    }
};

// 3. 實作合約 B：LINE Pay 支付
class LinePay : public IPaymentProcessor {
public:
    void pay(double amount) override {
        std::cout << "使用 LINE Pay 支付了 $" << amount << "\n";
    }
};
```

**這樣做的好處（解耦）：** 主程式只需要認識 `IPaymentProcessor` 這個接口，未來不論你想增加 Apple Pay 還是街口支付，主程式的程式碼完全不需要修改，這就是典型的「依賴反轉原則（Dependency Inversion Principle）」。

## 3. 當代系統常見的 API 訪問接口

如果你聽到的「訪問接口」是在網路或分散式系統的脈絡下 texture，它通常指的是 **API (Application Programming Interface)**。這不是類別內部的方法，而是系統與系統之間溝通的接口：

- **RESTful API 接口：** 透過 HTTP 動詞（GET, POST, PUT, DELETE）來存取伺服器資源。
    
    - `GET /api/users/123` $\rightarrow$ 獲取 ID 為 123 的使用者資料（相當於分散式系統中的 Getter）。
        
    - `POST /api/users` $\rightarrow$ 新增一個使用者。
        
- **RPC 接口 (如 gRPC)：** 允許一台電腦像呼叫本地端函數一樣，去呼叫遠端伺服器上的方法。
    

##  設計訪問接口有哪些原則？

1. **最小知識原則（Least Knowledge Principle）：** 接口要越簡單越好。不要對外暴露不需要的方法，能設為 `private` 的就不要變成 `public`。

2. **語意明確：** 接口的名稱應該要能直接反映它的行為（例如：`fetchData()` 比 `process()` 更好）。

3. **穩定性：** 接口一旦公開讓別人呼叫，就不應該隨意修改它的名稱或參數，否則所有呼叫你的程式碼都會崩潰。如果必須修改，通常會採取「版本控制」（如 `v1/api`、`v2/api`）或標註為 `deprecated`（棄用）。
