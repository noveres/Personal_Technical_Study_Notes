## **總成本  Cost   /  數量總和 Sum ( 總數量 Qty )

在會計、ERP 系統與程式開發（如 SQL 或資料庫設計）中，**Cost** 與 **Sum** 代表著完全不同維度的概念：

### **Cost（成本）** 
是一個**業務與財務欄位／概念**代表「取得產品或服務所花費的代價」，會是在資料庫欄位或商業邏輯中的 **資料本體** （如 `unit_cost` 或 `total_cost`）。。

  - **Unit Cost（單位成本）**：單一一件商品的成本。
    例如：1 瓶綠茶的進貨成本是 **$19 元**。
    
> 
> 如果全部只有一瓶，那它既是單位成本，同時也是總成本
> 
  
  - **Total Cost（總成本）**：這批或當前所有庫存商品的總價值。
    例如：庫存有 3 瓶綠茶，總成本是 **$219 元**。
  

### **Sum（總和／累加）** 
是一個**數學或程式運算動作**，代表「把多個數字加在一起的結果或函式」。
無論是在 Excel 中使用 `=SUM()`，還是在 SQL 資料庫中使用 `SELECT SUM(...)`，它的本質就是把一串數字通通加起來。
  
在成本計算中，會頻繁用到 **Sum** 這個動作，如把**每次進貨的數量加起來** 或 **把每次進貨的花費加起來**

| **比較項目** | **Cost（成本）**      | **Sum（總和）**    |
| -------- | ----------------- | -------------- |
| **本質**   | 商業／財務數據（資料）       | 數學／程式邏輯（動作/函式） |
| **代表含義** | 商品值多少錢？           | 把這些數字加起來是多少？   |
| **常見單位** | $ NTD / USD 等貨幣單位 | 無單位（取決於加總的是什麼） |

$$\text{新單位 Cost} = \frac{\text{Sum (所有進貨的 Cost)}}{\text{Sum (所有進貨的 Qty)}}$$

### 為什麼移動平均成本需要區分「冷熱資料」？
隨著 ERP 運作多年，庫存異動紀錄（`StockTransaction`）會積累幾百萬甚至幾千萬筆。如果每次要算一個料件的平均成本，**資料庫一定會被拉垮，查詢速度會變得極慢**。

因此，我們會將年代久遠**不會再被修改或寫入**的資料統計起來並封存，算出一組固定的 **期末結餘快照（Snapshot）**
-  `cold_cost_sum` = 截至 某個日期 的累積總成本
        
- `cold_qty_sum` = 截至 某個日期 的累積總數量
        
- 這兩個數字被沉澱（Archived/Snapshot）下來後就不再動了。
  
> 之後計算只要撈出來再加上去就行了

CREATE TABLE data_tier_config (

    end_date      DATE NOT NULL, -- 結束日期 (例如 '2019-12-31')
